# WeekCal 0.5.0 progress — 2026-09-21

## User validation from 0.4.6

- Win+D desktop persistence: confirmed working by user.
- Desktop icon reservation: user reports roughly 80% effective; some icons can remain too close to or overlapping the widget.
- Google Calendar on a second PC: user saw what looked like their schedule even without signing in. Root cause is the renderer's bundled demo timetable, not a copied Google session.
- Required UX: each person installs the same WeekCal build, clicks Conectar con Google, signs in to their own Google account, and never handles OAuth JSON files.

## Work completed on branch

Branch: `feature/google-account-icon-reflow-20260921`

### Google account flow
- Removed the end-user OAuth JSON picker.
- Added packaged app OAuth config lookup.
- Added Google account chooser flow with `openid`, `email`, Calendar Events, and Calendar List scopes.
- Added OAuth state validation.
- Added connected-account email display.
- Added Cambiar cuenta and Desconectar behavior.
- Calendar selections are cleared when switching/disconnecting.
- Tokens require Electron `safeStorage`.
- Build workflow generates `electron/google-app-config.generated.json` from repository secrets and removes it after packaging.

Required repository secrets for a functional installer:
- `WEEKCAL_GOOGLE_CLIENT_ID`
- `WEEKCAL_GOOGLE_CLIENT_SECRET`

### Disconnected state
- Removed the hardcoded demo timetable from `renderer/app.js`.
- No Google session = empty weekly grid and Sin conectar status.
- Google read failure no longer falls back to personal-looking sample events.

### Desktop icon reservation
- Added half-cell safety padding around the widget.
- After initial icon reflow, DesktopHost re-reads actual Explorer positions.
- Remaining overlapping icons are reassigned to free cells and retried for up to four correction passes.
- Successful reservation explicitly returns `verified: true` and `remainingOverlaps: 0`.
- If Explorer still leaves icons overlapping, the helper reports an error instead of pretending the reservation succeeded.

### Tests
- Added `tests/google-account-auth.test.js`.
- Extended `tests/windows-desktop-behavior.test.js` for post-move verification.
- Windows workflow now runs for pull requests to main.

## Remaining blocker before 0.5.0 installer can be delivered

The repository must contain the two Google OAuth application credentials as GitHub Actions secrets. They are application credentials, not user credentials. Once present, the PR build can produce a test installer in which each person signs into their own Google account without files.


## Additional finding: apparent calendar leak on another PC

The schedule shown before Google sign-in was not a copied Google session. It was the hardcoded demo timetable bundled in 0.4.6. This fallback has been removed from 0.5.0. A disconnected or failed Google connection now leaves the weekly grid empty.
